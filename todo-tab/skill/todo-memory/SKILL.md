# 待办（TODO.md）约定

每个工作区**一份 `TODO.md`**，位置 `~/.dsh/memory/<工作区>/TODO.md`，工作区名取会话工作目录的最后一段
（如 cwd 是 `/Users/me/Documents/dsh-plugins`，就写 `~/.dsh/memory/dsh-plugins/TODO.md`）。

## 先问再动：记录与删除都先问用户

用 `ask_user_question` 问。触发点是你自己的判断，不必等用户开口提待办：

- 会话里出现「不记就会忘」的事（等用户点头的决定、只能靠真实重启或真机验证的疑点、明确的清理项）
  → 问用户要不要记进本工作区的 TODO。
- 清单里已有条目看起来已办结（改动落地、验证通过、用户说不用做了）→ 问用户要不要删掉这一条。

两条硬规矩：

1. **没有得到肯定答复，不写也不删**。用户跳过某一问（提交了答案批次但那一问没选）或到点没答（pending）
   都按「不记、不删」处理：跳过不等于默认同意，删除尤其按「先留着」处理；下一次向用户开口时用一句话
   讲清「这条还没记」或「这条还没删」。唯一例外是用户已经在对话里明说要记、要删——那已经是点过头，
   直接做，不要再问一遍。
2. **一轮最多问一次**。同一轮里想记的、想删的条目放进同一个 `questions` 数组一次问完，
   不要一条一次 ask 连着打断用户。

提问怎么写：

- 问题 id 稳定、可机器识别：记录用 `todo_record_<工作区>`，一轮要记多条时每条补上序号
  （`todo_record_<工作区>-1`、`-2`…）；删除用 `todo_delete_<编号>`。同一次调用里 id 不能重复。
- 选项第一个放你推荐的那个，并加「(Recommended)」。记录：`记录 (Recommended)` / `不记录`；
  删除：`删除 (Recommended)` / `先留着`。
- 标题写成一句人话，先说清是什么事再问，别只丢编号——用户未必看过 TODO.md。
- 用户答过「不记」「先留着」或跳过不答之后，同一件事别在同一会话里反复提议；有新证据再提。
- 用户说「别问了」「你自己看着办」，本次会话就不再提问：记录与删除都按下面的铁律自己办，
  这种授权等于已经点过头，删除不必再逐条确认；但已经被明确拒过的条目仍然不记不删。
- 提问走不通时不要硬问：没有 `ask_user_question` 工具，或被宿主拒绝（`DELEGATED_CALLER`——被另一个
  活代理托管时不能和用户交互）——已获授权自办的照授权办，没获授权的把候选与待删清单写进返回结果，
  交给上层代理；自己就是根代理、没有上层代理时，写进回复正文。

## 铁律

- **只记未完成待办**：没有当日记录、没有归档、没有 `history.md`；不记讨论要点、不记结论。
- **「直接可做」的确定性小改动不写进 TODO**：当场做掉或直接在对话里说，别占清单——清单只承载「不记就会忘」的事。
- **写入只用插入式 `edit` 改单条**（新增走插入、办结删整条），禁止用 `write` 整份覆盖：同一工作区的所有会话共用这一份文件，并发会互相覆盖。
- **办结的条目经用户确认后删除整条**，不留 `[x]`、不加「已完成」小结；用户明确要求保留办结记录时，才就地标 `- [x]` 留着。
- 旧文件名 `today.md` / `history.md` 已废弃：见到就改写为 `TODO.md`，不要两份并存。

## 分组与编号

按三类分组，**没内容的小节不写**：

- `### A. 待裁决（需用户点头）`
- `### B. 需真实会话/重启验证`
- `### C. 小债与清理`

每条带稳定编号 `<工作区>-<序号>`（如 `dsh-plugins-3`）：

- 编号在工作区内**递增且永不复用**——办结的号不再给新条目，这样「`dsh-plugins-3` 是那件事」这个引用跨会话、跨天都成立。
- 跳号是正常的（办结过就留空洞），不要为了连续去重排。

## 字段

每条的标题是一句话事项，下面按需补 bullets：

- `做什么`：要做什么（几乎所有条目都该有）。
- `问题点`：现状 + 为什么是问题，带上已核对的证据（文件、行号、实测现象）。
- `推荐方案`：可选路 + 推荐哪条 + 理由。
- `怎么验`：代码层证明不了、只能跑一遍的事，写清具体操作 + 看什么现象。

篇幅与事项复杂度成正比：简单事项一行「做什么」就够，不要为填模板硬凑。

## 骨架

```markdown
# TODO（<工作区>）

### A. 待裁决（需用户点头）

- [ ] **<工作区>-1 <一句话事项>**
  - 做什么：<要做什么>。
  - 问题点：<现状 + 为什么是问题，含已核对的证据>。
  - 推荐方案：<可选路 + 推荐哪条 + 理由>。

### B. 需真实会话/重启验证

- [ ] **<工作区>-2 <一句话事项>**
  - 做什么：……
  - 怎么验：<具体操作 + 看什么现象>。

### C. 小债与清理

- [ ] **<工作区>-3 <一句话事项>**
  - 做什么：……
```

骨架文件随插件分发（路径见文末），需要时可整份拷出来当起点。

## 完整示例

```markdown
# TODO（dsh-plugins）

### A. 待裁决（需用户点头）

- [ ] **dsh-plugins-1 协议加版本号，避免再次静默丢帧**
  - 做什么：`hello`/`hello.ok` 带上协议版本，双方校验失败时回可读原因。
  - 问题点：形状不匹配的帧被静默丢弃，扩展端表现成永远 Connecting…，只能人肉探测定位。
  - 推荐方案：`hello` 增加 `proto: 2`；低版本收到明确的 `hello.reject` + 原因。

### C. 小债与清理

- [ ] **dsh-plugins-2 清理废弃脚本**
  - 做什么：删掉 `tools/` 下没人引用的两个探针脚本。
```
